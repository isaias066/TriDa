## Administrador del Sistema

| ID | Quiero (funcionalidad) | Para (razón / resultado) | Criterio de aceptación |
|---|---|---|---|
| HU-AD01 | QUIERO crear, modificar, desactivar y eliminar cuentas de usuario asignando roles específicos (Administrador, Analista, Operador, Auditor) | PARA garantizar que cada persona acceda únicamente a las funciones y datos que le corresponden según su cargo, manteniendo la seguridad del sistema | PUEDO gestionar el ciclo de vida completo de usuarios y roles desde el módulo de administración, con registro de cada acción en auditoría |
| HU-AD02 | QUIERO configurar y habilitar la autenticación multifactor (MFA) para los usuarios del sistema, incluyendo TOTP o SMS, y definir el tiempo de sesión inactiva | PARA añadir una capa adicional de seguridad que proteja el acceso al sistema ante credenciales comprometidas | PUEDO activar MFA por rol, definir tiempos de expiración de sesión y verificar que las sesiones inactivas se cierren automáticamente |
| HU-AD03 | QUIERO configurar los umbrales de score de riesgo (bloqueo automático >95%, niveles bajo 30-49%, medio 50-79%, alto 80-95%) y las reglas del motor de alertas desde la interfaz sin modificar código | PARA ajustar el comportamiento del sistema ante nuevos patrones de fraude o cambios en la política del banco sin depender del equipo técnico | PUEDO modificar umbrales, aplicar cambios en tiempo real y verificar que cada modificación queda registrada con mi nombre y marca temporal en auditoría |
| HU-AD04 | QUIERO visualizar en tiempo real el estado de salud de cada módulo del sistema (activo/degradado/inactivo), métricas de servidor (CPU, memoria, latencia) y el estado de conexión con el Core Banking | PARA detectar y actuar ante fallos o degradaciones antes de que afecten la detección de fraude o el equipo operativo | PUEDO consultar el panel de salud, recibir alertas automáticas cuando un componente falla y ver el histórico de incidentes técnicos |
| HU-AD05 | QUIERO programar el reentrenamiento periódico automático del modelo de Machine Learning (diario, semanal, mensual) utilizando las validaciones acumuladas de analistas | PARA que el modelo mejore continuamente su precisión con datos reales validados, adaptándose a nuevas técnicas de fraude sin intervención manual constante | PUEDO configurar la frecuencia de reentrenamiento, monitorear su ejecución y consultar las métricas del nuevo modelo antes de que entre en producción |
| HU-AD06 | QUIERO iniciar manualmente un reentrenamiento del modelo de IA en cualquier momento, comparar el nuevo modelo con la versión anterior mediante métricas (precisión, recall, F1-score) y revertir a una versión anterior si el rendimiento es inferior | PARA responder de forma ágil ante la detección de nuevos patrones de fraude no contemplados en el entrenamiento vigente | PUEDO lanzar el reentrenamiento manual, ver el historial de versiones del modelo y realizar rollback a una versión previa desde la interfaz de administración |
| HU-AD07 | QUIERO gestionar la integración del sistema con el Core Banking mediante APIs seguras (HTTPS/TLS 1.3, mutual TLS), incluyendo el monitoreo del flujo de datos y el manejo de reconexión automática ante interrupciones | PARA asegurar la continuidad del flujo transaccional en tiempo real y garantizar que ninguna transacción quede sin análisis de fraude por problemas de conectividad | PUEDO verificar el estado de la integración, revisar logs de errores de conexión y confirmar que la reconexión automática funciona sin pérdida de datos |
| HU-AD08 | QUIERO generar y exportar reportes regulatorios en los formatos exigidos por la Superintendencia Financiera de Colombia, cumpliendo con PCI-DSS, ISO 27001 y Ley 1581 de 2012 | PARA garantizar el cumplimiento normativo del banco ante auditorías y supervisiones regulatorias sin procesos manuales adicionales | PUEDO generar reportes regulatorios con el rango de fechas y métricas requeridas, exportarlos en el formato exigido y verificar que cubren todos los campos normativos |
| HU-AD09 | QUIERO consultar el registro de auditoría histórico completo (últimos 5 años mínimo) filtrando por fecha, cliente, tipo de transacción, analista y score de riesgo | PARA soportar análisis forenses de fraude, generar evidencia para procesos legales y responder a requerimientos de organismos regulatorios de manera oportuna | PUEDO acceder al módulo de auditoría, aplicar combinaciones de filtros y exportar los registros resultantes para investigación o presentación ante autoridades |
| HU-AD10 | QUIERO que todas las transacciones procesadas, scores asignados, decisiones automatizadas y acciones de analistas queden registradas de forma inmutable con marca temporal, ID único y firma de integridad | PARA garantizar la trazabilidad total del sistema y demostrar ante auditorías que ningún registro fue alterado, cumpliendo con los estándares PCI-DSS e ISO 27001 | PUEDO consultar cualquier registro de auditoría, verificar su firma de integridad y confirmar que ningún log puede ser modificado o eliminado por ningún usuario |

## Analista de Seguridad

| ID | Quiero (funcionalidad) | Para (razón / resultado) | Criterio de aceptación |
|---|---|---|---|
| HU-AN01 | QUIERO visualizar en el dashboard principal el flujo de transacciones procesadas en tiempo real y las alertas activas organizadas por nivel de criticidad (verde/amarillo/rojo) con código de color | PARA tener visibilidad inmediata del estado del sistema y priorizar la atención de las alertas más críticas sin perder tiempo buscando información dispersa | PUEDO ver el dashboard actualizado en tiempo real, identificar alertas por color y acceder a cualquier alerta en un clic para iniciar su revisión |
| HU-AN02 | QUIERO acceder a la vista detallada de cada alerta con datos completos del cliente, detalles de la transacción (monto, origen, destino, canal, dispositivo, ubicación en mapa) y el historial reciente de transacciones | PARA contar con toda la información necesaria para tomar una decisión de validación fundamentada sin necesidad de consultar sistemas externos | PUEDO revisar todos los campos de la transacción y el historial del cliente desde una sola pantalla y tomar acciones directamente sobre la alerta |
| HU-AN03 | QUIERO ver el score de riesgo calculado por la IA junto con la explicación en lenguaje natural de los factores que lo determinaron (dispositivo no reconocido, monto atípico, ubicación inusual, etc.) | PARA entender la lógica del modelo de IA y validar sus decisiones sin necesitar conocimientos técnicos avanzados de Machine Learning | PUEDO leer la explicación del score en lenguaje claro, entender qué variables lo dispararon y usar esa información para fundamentar mi clasificación de la alerta |
| HU-AN04 | QUIERO clasificar cada alerta en uno de cuatro estados: Fraude Confirmado, Falso Positivo, Pendiente de Investigación o Requiere Contacto con Cliente, con un comentario que documente mi razonamiento | PARA gestionar eficientemente el ciclo de vida de cada caso y alimentar el sistema de reentrenamiento con validaciones correctamente etiquetadas | PUEDO cambiar el estado de cualquier alerta, agregar un comentario justificativo y confirmar que la clasificación queda registrada con mi nombre, rol y marca temporal |
| HU-AN05 | QUIERO desbloquear manualmente transacciones previamente bloqueadas de forma automática cuando determine que se trata de un falso positivo, dejando una justificación obligatoria | PARA que clientes legítimos no sufran bloqueos prolongados incorrectos y para que cada desbloqueo quede trazable y retroalimente el reentrenamiento del modelo | PUEDO ejecutar el desbloqueo desde la vista de alerta, ingresar la justificación requerida y verificar que la transacción se libera y el caso queda registrado en auditoría |
| HU-AN06 | QUIERO utilizar filtros avanzados y combinables en el dashboard (rango de fechas, cliente, monto, nivel de score, tipo de transacción, canal, estado de alerta, analista asignado) con resultados en tiempo real | PARA localizar rápidamente alertas o transacciones específicas durante investigaciones de fraude sin tener que navegar manualmente por grandes volúmenes de datos | PUEDO aplicar múltiples filtros simultáneamente, ver los resultados actualizarse en tiempo real y exportar la selección filtrada para análisis externo |
| HU-AN07 | QUIERO recibir notificaciones en tiempo real según el nivel de criticidad de cada alerta: notificación en dashboard para nivel bajo, push para nivel medio, y push + correo electrónico para nivel alto (80-95%) | PARA actuar oportunamente ante alertas críticas sin depender de revisar el dashboard de forma activa, especialmente en casos de alto riesgo que requieren respuesta inmediata | PUEDO recibir las notificaciones por el canal correcto según el nivel de alerta y acceder directamente al caso desde la notificación sin pasos adicionales |
| HU-AN08 | QUIERO consultar reportes automáticos de desempeño del sistema con métricas clave: tasa de detección de fraudes, tasa de falsos positivos, tiempo de respuesta, monto protegido y tendencias temporales | PARA evaluar la efectividad del modelo de IA, identificar áreas de mejora y soportar la toma de decisiones sobre configuración de umbrales y prioridades de investigación | PUEDO acceder a reportes diarios, semanales y mensuales, visualizar las métricas clave y comparar el rendimiento entre períodos para detectar tendencias |
| HU-AN09 | QUIERO visualizar gráficos interactivos en tiempo real: línea de tiempo de transacciones vs alertas, distribución por criticidad, mapa de calor por canal y horario, y comparativa de falsos positivos vs verdaderos positivos | PARA identificar patrones visuales de fraude, detectar horarios o canales de mayor riesgo y optimizar la estrategia de monitoreo del equipo | PUEDO interactuar con los gráficos para explorar períodos específicos, filtrar por variables y exportar las visualizaciones para presentaciones o informes |
| HU-AN10 | QUIERO exportar cualquier reporte generado por el sistema en PDF, Excel/XLSX o CSV, personalizando el rango de fechas, las métricas incluidas y el nivel de detalle antes de exportar | PARA compartir información con otros departamentos, respaldar investigaciones formales y cumplir con requerimientos de reporte hacia entes regulatorios en el formato adecuado | PUEDO seleccionar el formato de exportación, configurar los parámetros del reporte y descargar el archivo con todos los datos correctamente estructurados |

## Operador de Monitoreo

| ID | Quiero (funcionalidad) | Para (razón / resultado) | Criterio de aceptación |
|---|---|---|---|
| HU-OP01 | QUIERO visualizar en tiempo real el flujo continuo de transacciones procesadas desde todos los canales bancarios (app móvil, web, cajero, punto de venta) con sus scores de riesgo asignados | PARA tener una visión global del volumen transaccional y detectar visualmente aumentos anómalos en la actividad que puedan indicar ataques coordinados o problemas técnicos | PUEDO ver el flujo de transacciones actualizado en tiempo real en el dashboard principal sin necesidad de acciones adicionales |
| HU-OP02 | QUIERO ver todas las alertas activas clasificadas por nivel de criticidad (bajo/medio/alto) con código de color y métricas resumidas del estado actual del sistema | PARA priorizar mi atención en los casos más urgentes y mantener una visión clara del estado general de la operación de detección de fraude en todo momento | PUEDO ver el listado de alertas activas ordenadas por criticidad, identificarlas por color y acceder a su detalle con un clic para evaluar si amerita escalado |
| HU-OP03 | QUIERO escalar alertas a un analista de seguridad específico o al analista disponible, incluyendo una nota obligatoria explicando el motivo del escalado | PARA que los casos que superan mi nivel de decisión sean atendidos por el personal autorizado de forma ágil y con el contexto necesario para actuar | PUEDO seleccionar el analista destino, ingresar la nota de escalado, confirmar el envío y verificar que el analista recibe la notificación inmediata del caso escalado |
| HU-OP04 | QUIERO recibir notificaciones automáticas en el dashboard para alertas de nivel bajo y notificaciones push para alertas de nivel medio, sin interrupciones innecesarias para casos de menor prioridad | PARA mantenerme informado de la actividad del sistema de forma proporcional al nivel de riesgo, actuando solo cuando el nivel de la alerta lo justifica | PUEDO recibir la notificación correspondiente al nivel de alerta y acceder directamente al caso desde ella para evaluarlo o escalarlo |
| HU-OP05 | QUIERO visualizar los bloqueos automáticos ejecutados por el sistema en transacciones con score superior al 95%, incluyendo los datos de la transacción bloqueada y el motivo | PARA tener trazabilidad de las acciones automáticas del sistema y poder reportar o escalar casos de bloqueo que requieran revisión por parte de un analista | PUEDO consultar el listado de transacciones bloqueadas automáticamente, ver su detalle completo y escalar el caso a un analista si identifico que puede ser un falso positivo |
| HU-OP06 | QUIERO consultar el historial de transacciones recientes de un cliente específico desde la vista de alerta, incluyendo scores anteriores y dispositivos utilizados | PARA contextualizar el comportamiento transaccional del cliente y evaluar si la alerta actual es coherente con un patrón inusual real o se trata de un comportamiento habitual del cliente | PUEDO acceder al historial del cliente desde la vista detallada de la alerta sin salir del sistema ni requerir acceso a bases de datos externas |
| HU-OP07 | QUIERO aplicar filtros de búsqueda en el dashboard por fecha, cliente, canal bancario, nivel de score y estado de alerta para localizar transacciones o alertas específicas | PARA agilizar la revisión de casos específicos durante mi turno de monitoreo y responder rápidamente a consultas sobre transacciones particulares | PUEDO combinar filtros, ver los resultados actualizados en tiempo real y navegar entre los casos filtrados sin perder la selección aplicada |
| HU-OP08 | QUIERO visualizar gráficos interactivos de métricas operativas: volumen de transacciones por hora, distribución de alertas por nivel y mapa de calor de actividad por canal y horario | PARA identificar tendencias operativas, detectar incrementos inusuales de actividad y anticipar picos de carga que puedan requerir mayor atención del equipo | PUEDO consultar los gráficos actualizados en tiempo real, ajustar el período de visualización y detectar visualmente anomalías en la distribución de transacciones |
| HU-OP09 | QUIERO consultar el perfil de riesgo dinámico de un cliente (historial de scores, patrones habituales, dispositivos registrados, ubicaciones frecuentes y alertas previas) | PARA enriquecer mi evaluación de una alerta con el contexto histórico del cliente y determinar si el patrón actual es realmente inusual respecto a su comportamiento registrado | PUEDO acceder al perfil de riesgo del cliente desde la vista de alerta y comparar el comportamiento actual con el historial sin necesidad de acceso administrativo |
| HU-OP10 | QUIERO verificar que el cliente afectado por un bloqueo automático recibió la notificación empática y no acusatoria a través de los canales oficiales (app, SMS, email) en un máximo de 30 segundos | PARA confirmar que el proceso de comunicación con el cliente funcionó correctamente y escalar si el cliente no fue notificado, evitando experiencias negativas innecesarias | PUEDO consultar el registro de la notificación enviada al cliente, ver el canal utilizado y la marca temporal, y escalar al analista si la notificación falló o superó el tiempo máximo |

## Programador

| ID | Quiero (funcionalidad) | Para (razón / resultado) | Criterio de aceptación |
|---|---|---|---|
| HU-PR01 | QUIERO implementar el módulo de ingesta de datos transaccionales en tiempo real mediante streaming continuo desde el Core Banking, extrayendo y normalizando los campos requeridos (monto, origen, destino, tipo, dispositivo, ubicación, hora) | PARA que cada transacción ejecutada en cualquier canal bancario sea capturada automáticamente y procesada en el formato estándar unificado que requiere el modelo de IA | PUEDO verificar que el módulo procesa transacciones en tiempo real desde todos los canales, normaliza los datos correctamente y no pierde registros ante picos de carga |
| HU-PR02 | QUIERO desarrollar el módulo de enriquecimiento automático de transacciones consultando fuentes internas (historial del cliente, dispositivos registrados, patrones habituales) y servicios externos de geolocalización | PARA que cada transacción llegue al modelo de IA con el contexto contextual completo que maximiza la precisión de detección de anomalías | PUEDO verificar que el módulo enriquece correctamente cada transacción, consulta las fuentes internas y externas en tiempo real y completa el proceso sin degradar la latencia del sistema |
| HU-PR03 | QUIERO implementar el modelo de Machine Learning que analiza cada transacción enriquecida y calcula un score de riesgo del 0% al 100% con un decimal, generando el resultado en menos de 500 milisegundos | PARA que el sistema pueda tomar decisiones automatizadas en tiempo real sin que la latencia del modelo impacte la experiencia del cliente en el canal bancario | PUEDO ejecutar pruebas de rendimiento que confirmen que el 100% de los scores se generan en menos de 500ms bajo carga de producción y que los valores son correctos respecto al modelo entrenado |
| HU-PR04 | QUIERO implementar la detección de patrones anómalos específicos: ubicaciones inusuales, montos atípicos, dispositivos no reconocidos, velocidad transaccional sospechosa, técnicas conocidas (botnets, ataques coordinados de microtransacciones) y simulación de comportamiento legítimo | PARA que el modelo identifique con alta precisión las técnicas de fraude más comunes en banca digital y genere scores representativos del riesgo real | PUEDO verificar que el modelo detecta correctamente cada tipo de patrón anómalo en los casos de prueba definidos con los scores esperados según el nivel de riesgo |
| HU-PR05 | QUIERO desarrollar el módulo de explicabilidad del score que genera automáticamente una descripción en lenguaje natural de los factores que determinaron la calificación de riesgo | PARA que los analistas puedan entender y validar las decisiones del modelo sin necesitar conocimientos de Machine Learning, cumpliendo con el estándar de IA explicable | PUEDO verificar que cada score generado incluye una explicación clara en español, identifica correctamente las variables de mayor peso y es comprensible para un analista no técnico |
| HU-PR06 | QUIERO implementar el motor de generación automática de alertas y notificaciones multicanal según el nivel de score: dashboard (bajo 30-49%), push (medio 50-79%), push+email (alto 80-95%) y todos los canales (bloqueo >95%) | PARA que el sistema notifique a los actores correctos por el canal adecuado en tiempo real, sin omisiones ni notificaciones incorrectas según el nivel de riesgo | PUEDO verificar con pruebas que cada nivel de score desencadena exactamente las notificaciones esperadas en los canales configurados dentro del tiempo de respuesta definido |
| HU-PR07 | QUIERO implementar el mecanismo de bloqueo automático e inmediato de transacciones con score >95% antes de su autorización en el Core Banking, con registro en auditoría y notificación al cliente en máximo 30 segundos | PARA evitar pérdidas económicas por fraudes de alto riesgo que el modelo identificó con alta certeza, manteniendo la trazabilidad completa de cada bloqueo | PUEDO verificar en pruebas que el bloqueo ocurre antes de la autorización en Core Banking, el registro en auditoría es inmediato y el cliente recibe la notificación dentro del SLA de 30 segundos |
| HU-PR08 | QUIERO implementar la integración segura con el sistema bancario central mediante APIs REST con HTTPS/TLS 1.3, mutual TLS, validación de integridad de datos, manejo de errores y reconexión automática ante interrupciones | PARA garantizar que la comunicación entre el sistema antifraude y el Core Banking sea segura, confiable y resiliente ante fallos de red sin pérdida de transacciones | PUEDO verificar que la integración cumple con todos los requisitos de seguridad (certificados, encriptación), maneja correctamente los errores de conexión y se reconecta automáticamente sin intervención manual |
| HU-PR09 | QUIERO implementar el módulo de registro de auditoría inmutable con marca temporal precisa, ID único de transacción, firma de integridad criptográfica y retención mínima de 5 años para todos los eventos del sistema | PARA garantizar el cumplimiento normativo PCI-DSS e ISO 27001 y proveer evidencia inalterable para auditorías regulatorias, investigaciones forenses y procesos legales | PUEDO verificar que ningún registro puede ser modificado ni eliminado por ningún usuario, la firma de integridad detecta cualquier alteración y los registros históricos están disponibles hasta 5 años atrás |
| HU-PR10 | QUIERO implementar el pipeline de reentrenamiento del modelo de IA que recopila automáticamente las validaciones de analistas (fraudes confirmados y falsos positivos), ejecuta el reentrenamiento, evalúa el nuevo modelo con métricas de validación y gestiona el historial de versiones con capacidad de rollback | PARA que el modelo se mejore continuamente con datos reales del sistema y pueda revertirse a una versión anterior si el nuevo modelo presenta peor desempeño en producción | PUEDO ejecutar el pipeline de reentrenamiento, comparar métricas del nuevo modelo vs el anterior, desplegar el nuevo modelo si supera al anterior y realizar rollback de forma controlada si es necesario |
